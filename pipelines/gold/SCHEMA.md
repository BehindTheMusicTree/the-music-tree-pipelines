## 1. Inputs

- `wikidata`'s `7_canonical_hierarchy.parquet` and `8_regional_hierarchy.parquet`: `item_id, item_label, item_url, parent_id, parent_label, parent_url, relation_type` — see `pipelines/wikidata/SCHEMA.md`.
- `wikidata`'s Bronze `wikidata_genre_descriptions.parquet` (`WIKIDATA_BRONZE_DIR`): the source of the tree nodes' `description` and Wikipedia `summary` — see `pipelines/wikidata/SCHEMA.md`.
- `musicbrainz`'s `6_artists.parquet`, `7_artist_members.parquet`, `8_artist_links.parquet`, `9_artist_release_groups.parquet`, `11_artist_aliases.parquet` — see `pipelines/musicbrainz/SCHEMA.md`.
- `musicbrainz`'s `5_songs.parquet`: `musicbrainz_recording_id, title, artist, artist_musicbrainz_id, youtube_video_id, youtube_unplayable_reason, youtube_view_count, genre_name, first_release_year` — see `pipelines/musicbrainz/SCHEMA.md`.
- `geohistory`'s `3_entity_succession.parquet`, `5_tradition.parquet`, `5_tradition_link.parquet`, `6_genealogy_lane.parquet`, `6_genealogy_tradition_lane.parquet`, `7_lane_order.parquet`, `7_band_fragment.parquet`, plus `1_cultural_entity.parquet`, `2_place_containment.parquet`, `5_music_anchor.parquet`, `8_entity_geometry.parquet`, `8_entity_footprint.parquet` for the region map (`GEOHISTORY_SILVER_DIR`) — see `pipelines/geohistory/SCHEMA.md`.

## 2. Outputs

**`1_canonical_genre_tree.json`** — `{"treeName": "canonical", "curationExportedOn": str, "tree": [<node>, ...]}`, one entry per root of `7_canonical_hierarchy`. `curationExportedOn` is the ISO 8601 `exportedOn` of the curation Bronze `manual_export.json` the tree was built from (required by grow-the-music-tree-api's tree import). A node is `{"id": str, "name": str, "children": [<node>, ...], "side": "pop" (optional, direct children of a root only), "isUnacceptedRoot": true (optional, roots only), "isUmbrella": true (optional, only on a node with children), "scene": "commercial" | "underground" (optional, per `manual_canonical_genre_scene.csv`), "primaryParents": [str] (optional), "secondaryParents": [str] (optional), "essentialSongs": [str] (optional, MusicBrainz recording ids ordered by `manual_essential_songs.csv` `position`), "description": str (optional, English Wikidata short description), "summary": str (optional, the item's `manual_summary_overrides.csv` override if it has one — a blank override emits no `summary` at all — else the English Wikipedia intro), "summarySourceUrl": str (optional, the Wikipedia article URL, only when `summary` is the Wikipedia intro, for CC BY-SA attribution)}`, recursive (validated against `src/gold/schemas/genre_tree.schema.json`), building on `the-music-tree-genre-kit`'s `CriteriaTreeImportSerializer`/`TreeField` import shape. `id` is the node's Wikidata QID (`item_id`), a stable identifier across label changes — consumed on the `grow-the-music-tree-api` side as the upsert key for `import_criteria_tree` (matches existing rows by `wikidata_id`, falling back to name only for id-less nodes). `side` is only ever present with value `"pop"`, per `manual_canonical_genre_pop_side.csv` below — see [DESIGN.md](DESIGN.md). `secondaryParents` lists the QIDs of the item's extra `5_secondary_parents` parents that are themselves canonical items (the canonical tree is imported first, so nothing else would resolve), minus edges removed by `manual_secondary_parents.csv`, plus its `add` edges; never `primaryParents`. `isUmbrella` is only ever present with value `true`, on a node whose `item_id` is `is_umbrella` in `7_canonical_hierarchy` (canonical tree only); the build raises on an umbrella without children. `isUnacceptedRoot` is only ever present with value `true`, on a root whose `item_id` is `is_accepted = false` in wikidata's `9_canonical_roots.parquet` (not in `manual_accepted_canonical_roots.csv`) — grow-the-music-tree-api flags it for admin review.

**`1_regional_genre_tree.json`** — same shape as `1_canonical_genre_tree.json` above (validated against the same `src/gold/schemas/genre_tree.schema.json`), but with `"treeName": "regional"` and built from `8_regional_hierarchy` instead — one entry per regional/geographic root (e.g. "music of Cape Verde") with that region's genres nested underneath. The item's extra `5_secondary_parents` parents that are regional or canonical items are emitted as `primaryParents`, except edges removed by `manual_secondary_parents.csv`; that list's `add` edges are emitted as `secondaryParents`. On a root, the first `primaryParents` ref becomes its main parent on import.

**`1_genre_match.parquet`** — `musicbrainz_recording_id, title, artist, artist_musicbrainz_id, youtube_video_id, youtube_unplayable_reason, youtube_view_count, first_release_year` (carried through from `5_songs.parquet`), plus:

| Column               | Type | Meaning |
| -------------------- | ---- | ------- |
| `wikidata_genre_name` | str, nullable | The chosen canonical `item_label` after precedence, or `null` if no tag resolved. |
| `wikidata_genre_item_id` | str, nullable | That genre's Wikidata QID. |
| `is_umbrella` | bool | The chosen genre is an umbrella (false when null). |
| `match_method`        | str  | One of `no_genre` (song has no genre tag), `exact`, `normalized`, `manual_alias`, `accepted_non_genre`, `wikidata_alias`, `disambiguated`, `ambiguous`, `unmatched` — see [DESIGN.md](DESIGN.md) for the cascade. |
| `secondary_genre_item_ids` | list[str] | QIDs of the song's other resolved genres left after precedence (none of them an ancestor of the chosen genre or of each other), by weight desc then `item_id`; empty when none. |
| `musicbrainz_genres` | list[struct{name: str, weight: int}] | Every `10_song_genre` tag of the song, resolved or not, by weight desc then name; empty when none. |

**`1_genre_match_unresolved.csv`** — `genre_name, song_count, weight_sum`, one row per unresolved tag name over all songs (most songs first) — written every run, even when empty. A data expert reviews this to promote each name into `manual_genre_alias.csv` or `manual_accepted_non_genre_tags.csv`. Also lists the `ambiguous` tags left unpicked on at least one song (counted over those songs), each awaiting a curated default in `manual_genre_disambiguation.csv`.

**`1_genre_match_report.json`** — `{"unresolvedGenreTagCount": int}`, the number of distinct `genre_name`s in `1_genre_match_unresolved.csv` — written every run, even when `0`, validated against `src/gold/schemas/genre_match_report.schema.json`.

**`1_umbrella_candidates.csv`** — `item_id, item_label, child_count, direct_song_count, descendant_song_count`: canonical genres with at least one child that are not yet umbrellas, sorted by `direct_song_count` descending then `item_id`. Written every run; a triage aid for the `umbrella_genres` curation list.

**`2_songs/part-NNNNN.ndjson.gz`** — gzip-compressed newline-delimited JSON, split into parts of 250,000 rows (`part-00000.ndjson.gz`, `part-00001.ndjson.gz`, ...; the directory is cleared each run). One line per row of `1_genre_match.parquet` (every song, none filtered): `{"musicbrainz_recording_id": str, "title": str, "artist": str, "artist_musicbrainz_id": str, "youtube_video_id": str | null, "youtube_unplayable_reason": str | null, "youtube_view_count": int | null, "genre_name": str | null, "first_release_year": int | null}` — exactly the fields grow stores, so a change to any other column never reaches the delta. `genre_name` is the resolved `wikidata_genre_name` when `match_method` is `exact`/`normalized`/`manual_alias`/`wikidata_alias`/`disambiguated`, else null. `manual_song_genre.csv` replaces `genre_name` with its `genre_item_id`'s tree name (null when empty); `1_genre_match.parquet` itself is pre-override. `manual_recording_youtube_video.csv` is applied upstream, in musicbrainz Silver `5_songs`. Checked in Polars before writing (raises `ValueError`): non-empty; `musicbrainz_recording_id` (`recording.gid`, a lowercase UUID), `title`, `artist`, `artist_musicbrainz_id` (`artist.gid`, a lowercase UUID) non-null; `musicbrainz_recording_id` unique; non-null `youtube_video_id` matches `^[A-Za-z0-9_-]{11}$`; non-null `youtube_unplayable_reason` is one of `not_found`, `not_embeddable`, `private`, `not_processed`, `region_whitelisted`; non-null `youtube_view_count` is non-negative and has a `youtube_video_id`; no null in `secondary_genre_item_ids`/`musicbrainz_genres`, and the genre never among `secondary_genre_item_ids`; `first_release_year` outside 1000-2100 is set to null (warning logged) instead of raising.

**`3_artists/part-NNNNN.ndjson.gz`** — same part layout as `2_songs`, but 10,000 rows each (directory cleared each run). One line per in-scope artist: every `artist_musicbrainz_id` of `1_genre_match.parquet`, the groups those artists are members of, and the members of all of those (one hop: a member's other bands aren't added), minus the special-purpose artists in `SPECIAL_PURPOSE_ARTIST_IDS` (Various Artists, `[unknown]`, `[anonymous]`, ...). Fields: `musicbrainz_artist_id`, `name`, `type`, `country`, `begin_year`, `end_year`, `ended`, `disambiguation` (nullable, from `6_artists`); `aliases` (sorted, distinct strings: `11_artist_aliases` plus the artist's `sort_name`, minus any equal to `name` ignoring case; empty list when none); `members` (`[{musicbrainz_artist_id, begin_year, end_year, ended, roles}]` from `7_artist_members`, members outside the scope dropped); `links` (`[{kind, url}]` from `8_artist_links`); `release_groups` (`[{musicbrainz_release_group_id, title, primary_type, secondary_types, first_release_year}]` from `9_artist_release_groups`); `image` (`{url, page_url, author, license, license_url}` from wikidata's `11_artist_images`, `url` being the 500 px Commons thumbnail, `author` and `license_url` nullable; null when the artist has no usable image; showing it requires crediting `author` and `license`, linked to `page_url`). Checked in Polars (non-empty; `musicbrainz_artist_id` and `name` non-null and `musicbrainz_artist_id` unique; no blank `name`; `musicbrainz_artist_id` and nested `musicbrainz_release_group_id` are lowercase UUIDs; non-null `type` is one of `person`, `group`, `orchestra`, `choir`, `character`, `other`; non-null `country` is two uppercase letters; a non-null `image` has https `url` and `page_url` and a non-blank `license`), then the first 1,000 rows are validated against `src/gold/schemas/artist.schema.json` to catch shape drift.

**`2_songs_snapshot.parquet`, `3_artists_snapshot.parquet`** — the key plus the columns of the export that grow stores (every `2_songs` column; every `3_artists` column), one row per exported row. Written atomically each run.

**`2_songs_delta/`, `3_artists_delta/`** — only written when `_synced/<name>_snapshot.parquet` exists with the same columns (the baseline the `infrastructure` run script copies there after grow merged a run successfully). `part-NNNNN.ndjson.gz`: the full-export rows (same shape and part size as `2_songs`/`3_artists`) whose key is new or whose value in any column differs from the baseline (null equals null). The log line gives the count per changed column. `deleted.ndjson.gz`: `{"<key>": str}` per baseline key absent from this run. Cleared each run.

**`4_genealogy.json`** — `{"columns": [{"id": str, "position": int, "lanes": [{"entityId": str, "label": str, "startYear": int | null, "endYear": int}]}], "bands": [{"entityId": str, "label": str, "fragment": int, "startPosition": int, "endPosition": int, "startYear": int | null, "endYear": int | null}], "successions": [{"predecessorId": str, "successorId": str}], "traditions": [{"wikidataId": str, "label": str, "start": int | null, "end": int | null, "anchorId": str | null, "inCanonicalTree": bool}], "traditionLinks": [{"sourceId": str, "targetId": str, "kind": "lineage" | "association"}]}`. Columns ordered by `position` (0 = west), lanes by start year; `successions` keep only edges between entities shown as a lane or band; `anchorId` is null for an unplaced tradition; `inCanonicalTree` is true when the tradition's QID is an `item_id` of `7_canonical_hierarchy`. Raises `ValueError` on zero traditions or columns, a column without lanes, or a schema violation (`src/gold/schemas/genealogy.schema.json`). POSTed to `grow-the-music-tree-api`'s `/v1/genealogy/import/`.

**`5_region_map/`** — `index.json`: `{"regions": [{"id": str, "name": str, "kind": "country" | "admin_unit" | "zone", "parentId": str | null, "childIds": [str], "zoneIds": [str], "bbox": [4 floats], "mainBbox": [4 floats], "centroid": [2 floats], "drillable": bool, "genres": [{"itemId": str, "rule": str, "relation": "canonical" | "regional" | "tradition"}], "songCount": int, "genreCount": int}]}`. Admin regions (countries and admin-1 units that carry a genre or contain one) have `parentId` `"world"` or their containing admin region, zones (historical or cultural regions, `parentId` null) list the admin regions they cover through `zoneIds` on those. `drillable` is true when `childIds` is not empty. `geometry/world.geojson` holds the top-level countries, `geometry/<adminId>.geojson` the children of each drillable admin region, `zones/<zoneId>.geojson` one zone; all are GeoJSON `FeatureCollection`s (`id` and `name` properties), coordinates rounded to 2 decimals, each file at most 300 KB. Raises `ValueError` on zero regions, a schema violation (`src/gold/schemas/region_map.schema.json`), an emptied geometry, or a file still above 300 KB at the coarsest simplification. **`5_region_map_unplaced.csv`** (`wikidata_id, anchor_id, reason`) lists the music-anchor rows whose anchor is not a place or has no geometry; **`5_region_map_report.json`** is `{"unplacedGenreCount": N, "files": [{"path", "bytes", "tolerance"}]}` — `files` lists each geojson with its size and the simplification tolerance it needed; the unplaced count is a soft warning, written even when 0, and a file above 90% of the cap also logs a warning.

**`_manifest.json`** — `{"builtOn": str, "curationExportedOn": str, "pipelinesCommit": str}`: the build's UTC ISO 8601 timestamp, the curation `exportedOn` stamped into both trees, and this repo's `git rev-parse HEAD`. Deleted at the start of every Gold run and written atomically (temp file + rename) only after every other output succeeded, so its presence means the Gold outputs are complete and consistent.

## 3. Manual CSVs

Read from `CURATION_BRONZE_DIR` (curation pipeline's Bronze output) — see [DESIGN.md](DESIGN.md#curation-mechanics) for how they're applied and validated. `manual_recording_youtube_video.csv` is read by musicbrainz Silver, see `pipelines/musicbrainz/SCHEMA.md`.

**`manual_genre_alias.csv`**: `musicbrainz_genre_name, wikidata_genre_name, reason` — a real genre named differently by musicbrainz than by wikidata.

**`manual_accepted_non_genre_tags.csv`**: `musicbrainz_genre_name, reason` — permanent non-genre folksonomy noise (e.g. `asmr`, `birdsong`) that should never resolve to a genre.

**`manual_genre_disambiguation.csv`**: `musicbrainz_genre_name, item_id, is_default, reason` — one row per candidate genre of an ambiguous tag; `is_default` `true` on at most one per tag (the pick when the song's other genres don't decide).

**`manual_genre_disambiguation_context.csv`**: `musicbrainz_genre_name, item_id, context_item_id, reason` — a song also carrying `context_item_id`, or a genre under it, resolves the tag to the candidate `item_id`.

**`manual_canonical_genre_pop_side.csv`**: `root_genre_name, pop_child_genre_name, reason` — for a canonical root, which direct child(ren) are `the-music-tree-genre-kit`'s "pop" side; a root may have zero, one, or several pop children (one row each), but at least one direct child must remain "core".

**`manual_secondary_parents.csv`**: `item_id, parent_id, action, reason` — `action` `add` or `remove`. Ids are `Q…` or `LOCAL:…`.

**`manual_essential_songs.csv`**: `item_id, musicbrainz_recording_id, position, reason` — `position` unique per item.

**`manual_summary_overrides.csv`**: `item_id, summary, reason` — a genre's `summary`; a blank `summary` suppresses the Wikipedia intro (no `summary`, no `summarySourceUrl`).

**`manual_canonical_genre_scene.csv`**: `item_id, scene, reason` — `scene` `commercial` or `underground`, set on that tree node only (not inherited). `item_id` must exist in one of the two trees; a row for the other tree's item is ignored.

**`manual_song_genre.csv`**: `musicbrainz_recording_id, genre_item_id, reason` — replaces a song's computed genre (`musicbrainz_recording_id` is the song's representative recording id; takes precedence over `manual_genre_precedence.csv`); empty `genre_item_id` makes it genreless.

All four raise on a blank required value, a malformed id, a duplicate key, an `item_id`/`genre_item_id` in neither tree, or (recording lists) a recording not in the songs.
